# flowai-cli — standalone distribution CLI for the flowai framework

> **Inheritance:** This is a standalone repo. It does NOT inherit AGENTS.md from
> the upstream `korchasa/flowai` monorepo; instead, project-level rules below
> are deliberately self-contained.

## Purpose

CLI tool for distributing the flowai framework into AI-IDE config directories
(Cursor, Claude Code, OpenCode, OpenAI Codex). Published to JSR as
`@korchasa/flowai`. Bundles a pinned framework release tarball into
`src/bundled.json` at publish time — zero network dependency at runtime.

## Stack

- TypeScript (strict), Deno, JSR
- CI/CD: `.github/workflows/ci.yml`

## Relationship to upstream flowai

- **Framework source of truth**: <https://github.com/korchasa/flowai>
  (skills, commands, agents, packs).
- **Bundle source**: `framework-v<version>` GitHub release on the upstream
  repo. The asset `framework.tar.gz` is pinned by SHA-256 in `framework.lock`.
- **Requirements/design docs**: live upstream
  (`documents/requirements.md`, `documents/design.md`). FR-link comments in
  source files (`// implements [FR-X](https://github.com/korchasa/flowai/...)`)
  point to upstream anchors.

## Architecture

- **BundledSource** (`src/source.ts`): reads `src/bundled.json` (generated by
  `scripts/bundle-framework.ts` from a pinned framework release tarball).
- **FsAdapter** (`src/adapters/`): abstracts filesystem for deterministic
  testing (`InMemoryFsAdapter`).
- **Config**: `.flowai.yaml` — version, ides, skills (include/exclude),
  commands (include/exclude), agents (include/exclude).
- **Agent transform**: universal frontmatter → IDE-specific subset per IDE.
- **IDE auto-detection**: presence of `.cursor/`, `.claude/`, `.opencode/`.

## Bundle pinning contract (FR-DIST.BUNDLE.PIN)

`framework.lock` holds three mandatory fields:

- `version` (`MAJOR.MINOR.PATCH`) — the framework release tag without the
  `framework-v` prefix.
- `commit_sha` (40-hex) — the upstream commit pinned by that release.
- `tarball_sha256` (64-hex) — SHA-256 of the `framework.tar.gz` asset.

`scripts/bundle-framework.ts` downloads the tarball, verifies the SHA-256,
untars, and bundles. Any download, schema, or checksum failure aborts —
there is no silent fallback path.

Bump the lock via `deno task bump-framework <version>` (requires `gh` CLI).

## Generated files (gitignored)

- `src/bundled.json` — `deno task bundle`.
- `src/_version.ts` — same task; mirrors `deno.json` version.

`scripts/task-check.ts` auto-bootstraps both files with placeholders if
absent, so type-check and unit tests run on a fresh clone before the first
real bundle.

## Test execution

- All tests require `-A`. `deno test src/...` without it fails on permission
  errors that look like real bugs.
- `deno task check` runs fmt → lint → type-check → tests for `src` + `scripts`.

## Key decisions

- Bundle source is a pinned GitHub release tarball, NOT a git submodule or
  in-repo `framework/` directory. Runtime stays offline.
- CLI release line restarts at `0.13.0` (the next minor after the last
  monorepo release at `0.12.9`). Framework versions are independent.
- JSR publish via `deno publish`, OIDC auth in CI.
- Acceptance tests live upstream (in the monorepo); this repo ships only TS
  unit tests.

## Verification

- `deno task check` — fmt + lint + type-check + tests.
- `deno task bundle` — pin a framework release tarball and regenerate
  `src/bundled.json` / `src/_version.ts`.
- `deno task bump-framework <version>` — update `framework.lock` to a newer
  framework release.
